# LabLog

研究室に来た時刻・帰った時刻と、PC でどんな作業をしたかを自動で記録して、日報を残すための Windows アプリです。

> **ご注意**：LabLog は AI で作成したアプリです。動作や安全性は保証できません。

- **タイムカード機能**：入退室時刻の記録。判定方法（Wi-Fi・PC の操作・手動）を選べます。
- **作業内容の記録**：PC でした操作を記録。分類ごとの時間やタイムラインで振り返れます。
- **日報機能**：その日の作業内容をメモ。記録から自動で作成することもできます。
- **Microsoft アカウント連携**：入退室履歴をスマホからも確認できます（使う場合だけ）。

記録はすべてこの PC の中に保存し、外部には送りません（Microsoft アカウント連携の利用時を除く）。何を記録するかは一つずつ選べます。

## 使い始める

1. [Releases](https://github.com/ISCT-STLab/lablog/releases) から、いちばん新しい `LabLog-<バージョン>.zip` をダウンロードして展開します。展開する場所はどこでもかまいません（ダウンロードのフォルダのままで大丈夫です）。
2. 展開したフォルダの **`setup.cmd`** をダブルクリックします。はじめに注意書き（AI で作成したアプリであること）が出るので、続けるなら `Y` を押します。
   - Python 3.11 以降が入っていなければ、winget で入れるかを聞かれます（このユーザーだけに入れます。管理者の権限は要りません）。
   - セキュリティの警告が出たら「実行」を押します（インターネットから取ったファイルに出る確認です）。
3. インストールが終わると LabLog が起動し、ブラウザで **初期設定** の画面が開きます。日報・作業内容の記録・入退室の判定方法などを選びます。初期設定を終えるまでは、何も記録しません。

- インストール先は `%LOCALAPPDATA%\Programs\LabLog` です。ログオンしたときに自動で起動します。
- インストールが終わったら、展開したフォルダは消してかまいません。
- あとから開くときは、スタートメニューの **LabLog** を開きます（起動中ならダッシュボードが開くだけです）。
- 初期設定は、設定の画面の右上の「初期設定をやり直す」で、もう一度開けます。

## 更新する

設定の画面の **LabLog について** で「更新を確認」を押します。新しいバージョンがあれば変更点が出るので、「更新する」を押すと、ダウンロードして切り替え、LabLog を起動し直します。

- **安定版**（正式に公開されたバージョンだけ）と **ベータ版**（公開前のバージョンも）を選べます。
- 自動では確認しません。確認するときに配布元（GitHub）へ送るのは、バージョンを尋ねるリクエストだけです。
- 記録と設定はそのまま引き継ぎます。新しいバージョンを起動できなかったときは、自動で前のバージョンに戻します。

## アンインストール

Windows の **設定 → アプリ → インストールされているアプリ** で、LabLog の「…」から「アンインストール」を押します（`%LOCALAPPDATA%\Programs\LabLog\uninstall.cmd` を実行しても同じです）。自動起動とスタートメニューのショートカットも消します。Microsoft アカウントと連携していれば、連携も解除します（OneDrive の LabLog の記録を消し、スマホ版をサインアウトします）。日報の AI（LabLog から入れた Ollama とモデル）と、記録したデータ（`%LOCALAPPDATA%\LabLog`）も消すかどうかは聞かれます（初めは残します）。もとから入っていた Ollama は残し、LabLog がダウンロードしたモデルだけを消せます。

記録を残したままアンインストールすれば、入れ直したときにそのまま引き継ぎます。記録も消すときは、消す前にデスクトップへバックアップ（ZIP）を保存するかを聞かれます。

## 記録を引き継ぐ（バックアップ）

入れ直すときや、別の PC に移すときに使います。

- **保存**：設定の画面の「LabLog について」→「バックアップを保存」で、記録と設定を ZIP に保存します（ダッシュボードの合言葉は含みません）。
- **戻す**：設定の画面、または初期設定の「はじめに」で「バックアップから戻す…」を押して ZIP を選びます。LabLog が起動し直して、記録を差し替えます。差し替える前の記録は、データのフォルダの `before-restore-<日時>` に残します。

## 入退室の判定

設定の画面の **入退室の判定** で、判定のしかたを選びます。

| 判定方法 | 入室 | 退室 |
|---|---|---|
| Wi-Fi で判定 | 「研究室」として登録した Wi-Fi につながる | 登録していない Wi-Fi につながる。Wi-Fi が切れたら仮退室にし、4 時間戻らなければ退室 |
| この PC の操作で判定 | この PC を手元で操作し始める | 15 分操作がない・ロックしたら仮退室にし、4 時間戻らなければ最後に操作した時刻で退室 |
| 手動で記録 | 日別画面の「入室」 | 日別画面の「退室」（押し忘れたまま 4 時間操作がなければ、最後に操作した時刻で退室） |
| 記録しない | — | — （PC作業時間だけを記録し、場所は「自宅」か「その他」として数える） |

- **Wi-Fi の登録**：研究室にいるときに、設定の画面の「入退室の判定」（Wi-Fi で判定を選んだとき）で「研究室として登録」を押します。研究室専用と大学共通の Wi-Fi（ScienceTokyo など）は、どちらも登録します。eduroam や Wi2 は他の場所にもあるので登録しません。スマホのテザリングのように研究室でも外でも使う Wi-Fi は「判定に使わない」にします。
- **手動の入室・退室**：「記録しない」以外では、日別画面の「入退室状況」にある「入室」「退室」で切り替えられます。押し忘れたときは、その下の「今日の入退室履歴」で時刻を直せます。
- **リモートデスクトップ**：Windows のリモートデスクトップで外から操作している間は、研究室にいないとみなし、作業時間は「自宅」として数えます（Chrome リモートデスクトップなど、画面をそのまま映すソフトは見分けられません）。
- **滞在時間** は、PC を閉じてゼミに出ていた時間（仮退室から戻るまで）も含みます。**PC作業時間** は、5 分以上操作がなかった時間（離席）を除き、研究室・自宅・その他に分けて集計します。
- 1 日は朝 5 時で区切ります。深夜の作業は前日分です。夜通しいた場合も 1 回の滞在として記録します。
- 判定がずれたときは、日別画面の入退室履歴から、時刻を直したり、追加・削除したりできます（ほかの入退室と重なる時刻や、これからの時刻は入れられません）。
- 1 分未満の滞在（入室をすぐ取り消した・研究室の Wi-Fi に一瞬つながっただけ など）は残しません。
- 4 時間・15 分・5 分などの時間は設定で変えられます。

## 記録するもの

どれも初期設定で一つずつ選び、あとから設定の画面の **作業内容の記録** で変えられます。

| 項目 | 内容 |
|---|---|
| アプリとウィンドウ | 前面にあるアプリ名とウィンドウ名、使っていた時間（5 秒ごとに確認）。「アプリ名だけ」「記録しない（PC作業時間だけ）」も選べます |
| ファイルの編集履歴 | 監視フォルダ内で作成・保存・削除・名前変更したファイル（パス・時刻・サイズだけ。中身は読まない）。`.git`・`node_modules`・`AppData`・キャッシュなど、アプリが裏で書くものは除く |
| Git | 監視フォルダ内のリポジトリのコミット、未コミットの変更数 |
| ブラウザ履歴 | Chrome・Edge で開いたページの URL とタイトル（シークレット／InPrivate は対象外）。画面に表示したページだけを表示・日報に使い、開いたままのタブがバックグラウンドで読み込まれただけのものは除きます |
| 最近使ったファイル | Windows の「最近使ったファイル」の一覧 |
| Claude Code の会話 | 会話の題名・作業フォルダ・やりとりした時刻（分単位）。ウィンドウ名が「Claude」だけのときに、この題名で補います。会話の中身は記録しません |
| 画面の文字 | 対象のアプリ（初期設定は Claude・ChatGPT・To Do・Teams・Zoom・MATLAB・ターミナル・PowerShell。ウィンドウ名から作業内容が分からないもの）が前面にあるとき、5 分に 1 回そのウィンドウだけを写し、Windows 標準の文字認識で文字にしたもの。画像は保存せず、文字は 3 日で消します（作った日報に書かれた分は残ります）。日報を除き、スマホには送りません |

- 初期設定を終えたあとも、閲覧履歴などは **初期設定を終えた時刻より後** の分だけを取り込みます。
- 上部の **■ 一時停止** を押すと、作業内容の記録（上の表のすべて）を止めます。入退室の判定は続けます。止めている間は「一時停止中」と出て、ボタンは **▶ 再開** に変わります。記録しているときは「記録中」と出ます（カーソルを当てると、記録しているものが出ます）。
- 画面の文字の読み取りは、2 分以上操作していないときや「記録しないアプリ」でも行いません。読み取った文字は日別画面の「画面から読み取った文字」で確かめられ、設定の「画面の文字」でまとめて消せます。
- 設定の **記録しないアプリ** に入れたアプリは、時間だけを「(除外)」として残し、名前とウィンドウ名は記録しません。
- 分類（コーディング・解析／文書・資料作成 など）のルールは設定で変えられ、過去の記録にも反映されます。

## コミットの通知

監視フォルダ内のリポジトリで、ファイルを編集しているのに 2 時間以上コミットしていないと、Windows の通知で知らせます。
一度知らせたら、同じ時間がたつまで再通知しません。時間と通知のオン・オフは設定で変えられます。

## 日報

初期設定で選び、あとから設定の画面の「日報」でも変えられます。

- **日報を自動で作成する**：退室が確定したときと、日付が変わったときに、その日の記録から日報を作ります。日別画面で書き直して「保存」すると、自動では上書きしなくなります。
- **日報の作成に AI を使用する**：記録を要約して文章で作ります（1 日分で 1 分ほど）。オフのときは、集計から箇条書きで作ります。メール・ファイル整理・分類できなかったサイト（動画など）・中身の分からないウィンドウは、AI に渡す前に除いています。
- 自動で作成しないときは、日別画面の「書く」で書きます（「自動生成」で作ることもできます）。

### ローカルAI（Ollama）

初期設定の画面で「日報の作成に AI を使用する」をオンにすると、Ollama が入っているかを調べ、入っていなければボタンでインストールとモデルのダウンロードまで行えます。PC のメモリに合わせて、モデル（16 GB 以上なら `qwen3:8b`、8 GB 以上なら `qwen3:4b`）を勧めます。

手で入れるときは、`winget install Ollama.Ollama`（または https://ollama.com から）で Ollama を入れ、`ollama pull qwen3:8b`（約 5GB）でモデルをダウンロードします。設定の画面で「準備完了」と表示されれば使えます。

LabLog は `127.0.0.1`（この PC）の Ollama にしか接続しません。PC 外の URL は設定できないようにしてあり、プロキシも使いません。
Wi-Fi を切った状態でも日報を作れるので、外部に送っていないことを確かめられます。

## 画面の演出

その日の作業時間に応じて、ページの背景（壁紙）とカードが少しずつ豪華になります。この度合いを「フロー」と呼び、日別画面の「研究室・PC作業時間」のタイルの右上に 4 つの目盛りで出します。触れる（マウスを重ねる）と、フローが深まるまでの時間が出ます。

| フロー | 目安（PC作業時間。大学にいた時間の 75% のほうが長ければそちら） | 見た目 |
|---|---|---|
| 0 | 1 時間未満 | 黒・グレー・シルバーのグラデーション（明るい表示では銀色） |
| 1 | 1 時間〜 | 背景にうっすら青い光 |
| 2 | 3 時間〜 | 青・緑・紫の光、カードがすりガラスに |
| 3 | 5 時間〜 | 青・紫・ピンク・オレンジの光、数値のタイルに光る縁取り（研究室・PC作業時間のタイルは半透明のまま） |
| 4 | 7 時間〜 | いちばん鮮やかな光がゆっくり動く |

- 月の画面は、作業した日の平均でフローが決まります。設定画面はいつもフロー 0 です。
- タイムラインや分類別の色は意味を持つので変えません。
- 見た目を確かめるときは、URL に `?level=4` を付けるとフローを固定できます（例：`http://127.0.0.1:8765/?level=4`）。
- 日報は罫線入りのノート風に、手書き風の文字で表示します。文字は Klee One（SIL Open Font License 1.1。`lablog/web/fonts/OFL.txt`）を日本語の常用範囲に絞って同梱しています。

## Microsoft アカウント連携

PC と同じ画面を、スマホ（iPhone・Android）やタブレットのブラウザで開けるビューアーがあります（URL は設定の画面の「Microsoft アカウント連携」に出ます）。
ホーム画面に追加すると、アプリと同じようにアイコンから開けます（iPhone は Safari の共有ボタン →「ホーム画面に追加」、Android は Chrome のメニュー →「ホーム画面に追加」）。

- **必要なもの**：個人の Microsoft アカウントと、この PC で同期している個人用の OneDrive（大学の Microsoft アカウントでは使えません）。
- **PC ではサインインしない**：PC の LabLog は OneDrive のフォルダに書き出すだけです。スマホからは、PC の OneDrive と同じアカウントでサインインします（設定の画面に、PC の OneDrive のアカウントが出ます）。
- **しくみ**：PC の LabLog が要約を OneDrive のアプリ専用フォルダ（`OneDrive\アプリ\LabLog`）に書き出し、ビューアーは個人の Microsoft アカウントでサインインしてそれを読みます。ビューアーが触れるのはこのフォルダだけです。
- **OneDrive に置くもの**：入退室・滞在時間・PC作業時間（大学／自宅）・分類別の時間・タイムラインの分類・日報。日報は、設定の「日報もスマホに送る」でオフにできます。
- **PC だけに残すもの**：ウィンドウ名、閲覧したページ、編集・使用したファイル、Git、Wi-Fi 名。ただし、日報に書かれたもの（ファイル名やコミットの文など）は、日報と一緒にスマホにも出ます。記録そのもの（`lablog.db`）は OneDrive には置きません。
- **書き出すタイミング**：5 分ごと（変わった分だけ）と、入退室・日報の作成・保存・滞在の修正のとき。設定の「今すぐ同期」でもすぐ書き出せます。
- **スマホで直す**：日報の書き直しと滞在の追加・修正・削除ができます。直した内容は OneDrive の `edits` に置かれ、PC の LabLog が次に動いたとき（30 秒ごとに確認）に取り込みます。それまでは「PC へ反映待ち」と表示します。
- **始め方**：ビューアーを開いてサインインすると、OneDrive に `アプリ\LabLog` フォルダができます。PC の LabLog は目印の `viewer.json` を見つけると（数分以内）、書き出しを始めます。
- **連携をやめる**：設定の「Microsoft アカウント連携」で「連携する」をオフにします。OneDrive 上の記録を消し、スマホ版はサインアウトします（PC の記録は残ります）。

## データの保存場所

`%LOCALAPPDATA%\LabLog`（OneDrive の外なので、クラウドには同期されません。アプリを更新しても、そのまま引き継ぎます）

| ファイル | 内容 |
|---|---|
| `lablog.db` | 記録（SQLite）。表の形を変える更新の前には `backups` フォルダに写しを作ります |
| `settings.json` | 設定 |
| `dashboard.key` | ダッシュボードの合言葉（この Windows のアカウントだけが開けるようにするためのもの） |
| `lablog.log` | 動作ログ（困ったときに見る） |

月ごとの入退室は、月画面の「CSV で書き出す」から Excel で開ける形式で保存できます。
ダッシュボードは `127.0.0.1` だけで待ち受けるので、ほかの PC からは開けません。開くには合言葉が要ります（スタートメニューの LabLog から開くと、自動で付きます）。

## 困ったとき

- **「LabLog から開き直してください」と出る**：ブックマークなどから直接開いたときに出ます。スタートメニューの LabLog から開き直してください（一度開けば、次からはそのブラウザで開けます）。
- **Wi-Fi が「未接続」のままになる**：Windows の設定 → プライバシーとセキュリティ → 位置情報 で「デスクトップアプリに位置情報へのアクセスを許可する」をオンにしてください（Windows の仕様で、Wi-Fi 名の取得に必要な場合があります）。
- **ダッシュボードが開かない**：スタートメニューの LabLog から開き直してください。ポート 8765 をほかのアプリが使っているときは、8766 以降の空いているポートで起動します。
- **LabLog を終了したい**：設定の「LabLog について」の「LabLog を終了」を押します。もう一度使うときは、スタートメニューの LabLog を開きます（ログオンしたときにも起動します）。
- **更新したあとに「前のバージョンに戻しました」と出る**：新しいバージョンを起動できなかったので、自動で前のバージョンに戻しています。`%LOCALAPPDATA%\Programs\LabLog\launcher.log` を添えて、LabLog を配った人に知らせてください。

## 開発者向け

- Python 3.11 以降の標準ライブラリだけで動きます（追加のインストールは不要）。
- リポジトリのフォルダから動かすとき：`python LabLog.pyw`。ログオン時に自動で起動するには `install_autostart.ps1`、やめるには `uninstall_autostart.ps1` を実行します（このときは LabLog の画面からは更新せず、`git pull` で更新します）。
- テスト：`python -m unittest`（Node.js があれば画面の回帰テストも実行。個別実行は `node --test tests/web_report.test.cjs`）
- 本番のデータと分けて試すとき：`python LabLog.pyw --port 8766 --data-dir <テスト用フォルダ>`
- ビューアーを PC で試すとき：`python tools/preview_viewer.py`（いまの記録の写しを使い、サインインなしで `http://127.0.0.1:8770/` に開く）
- ビューアーを公開し直すとき：`python tools/publish_viewer.py --push`（`lablog/web` の画面ファイルを `..\lablog-viewer` に写して GitHub の gh-pages ブランチに送る。記録は含めない）

### リリースの手順

1. `lablog/__init__.py` の `__version__` を上げます（正式なバージョンは `1.1.0`、ベータ版は `1.1.0b1` のように）。
2. `CHANGELOG.md` の一番上に `## <バージョン>` の節を作り、変更点を書きます。
3. テストを通します（`python -m unittest`）。
4. `python tools/release.py` で、`dist/LabLog-<バージョン>.zip` と、リリースの説明に使う `dist/LabLog-<バージョン>-notes.md` を作ります。
5. GitHub の [Releases](https://github.com/ISCT-STLab/lablog/releases) で「Draft a new release」を押し、タグを `v<バージョン>` にして、ZIP を添付し、説明に `LabLog-<バージョン>-notes.md` の中身を貼って公開します。ベータ版のときは「Set as a pre-release」に印を付けます。
   - `gh` を入れていれば：`gh release create v<バージョン> dist/LabLog-<バージョン>.zip --title "LabLog <バージョン>" --notes-file dist/LabLog-<バージョン>-notes.md`（ベータ版は `--prerelease` を付ける）
6. ブラウザ版（ビューアー）を公開し直します：安定版は `python tools/publish_viewer.py --push`、ベータ版は `python tools/publish_viewer.py --beta --push`（`…/lablog/beta/` に置きます）。正式なバージョンがまだ無いあいだは、ベータ版を出すときも安定版を公開し直します（PC の LabLog がスマホ用に案内するのは安定版のため）。ブラウザ版は、自分より古い PC の LabLog を見ると「更新してください」と知らせます。

LabLog の「更新を確認」は、GitHub の API を認証なしで使います。リポジトリが公開されていないと、新しいバージョンを見つけられません。

### ブラウザ版を研究室の組織に移す（最初のリリースのときに一度だけ）

1. GitHub で `ISCT-STLab/lablog` を Public にします（無料のプランでは、GitHub Pages は公開リポジトリだけで使えます）。
2. 新しい公開用フォルダから送ります：`python tools/publish_viewer.py --site ..\lablog-pages --push` と、`python tools/publish_viewer.py --site ..\lablog-pages --beta --push`（`ISCT-STLab/lablog` の gh-pages ブランチに送ります）。
3. リポジトリの Settings → Pages で、gh-pages ブランチを公開します（`https://isct-stlab.github.io/lablog/`）。
4. Microsoft のアプリ登録（Azure portal → アプリの登録 → 認証）のリダイレクト URI に、`https://isct-stlab.github.io/lablog/` と `https://isct-stlab.github.io/lablog/beta/` を足します。
5. 自分の `settings.json` の `cloud.viewer_url` を空にします（空なら配布元のブラウザ版を使います）。前のブラウザ版（`kkosugitm.github.io/lablog`）は、移し終えてから消します。
