# LabLog

研究室に来た時刻・帰った時刻と、PC でどんな作業をしたかを自動で記録して、日報を残すための Windows アプリです。

- **研究室の入退室を記録する**：来た時刻・帰った時刻と滞在時間。判定のしかた（Wi-Fi・PC の操作・手動）は選べます。
- **作業内容を記録する**：使ったアプリやファイル、見たページなどを記録し、分類ごとの時間やタイムラインで振り返れます。
- **日報を残す**：その日の記録から日報の下書きを自動で作れます（自分で書くこともできます）。
- **スマホで見る**：同じ画面を、スマホのブラウザでも見られます（使う場合だけ）。

記録はすべてこの PC の中に保存し、誰にも送りません。何を記録するかは一つずつ選べます。

## 使い始める

1. [Releases](https://github.com/ISCT-STLab/lablog/releases) から、いちばん新しい `LabLog-<版>.zip` をダウンロードして展開します。
2. 展開したフォルダの **`setup.cmd`** をダブルクリックします。
   - Python 3.11 以降が入っていなければ、winget で入れるかを聞かれます（このユーザーだけに入れます。管理者の権限は要りません）。
   - セキュリティの警告が出たら「実行」を押します（インターネットから取ったファイルに出る確認です）。
3. インストールが終わると LabLog が起動し、ブラウザで **初期設定** の画面が開きます。説明に沿って、日報のつけ方・記録するもの・入退室の判定方法などを選びます。初期設定を終えるまでは、何も記録しません。

- インストール先は `%LOCALAPPDATA%\Programs\LabLog` です。ログオンしたときに自動で起動します。
- あとから開くときは、スタートメニューの **LabLog** を開きます（起動中ならダッシュボードが開くだけです）。
- 初期設定は、設定の画面の右上の「初期設定をやり直す」で、もう一度開けます。

## 更新する

設定の画面の **LabLog の更新** で「更新を確認」を押します。新しい版があれば変更点が出るので、「更新する」を押すと、ダウンロードして切り替え、LabLog を起動し直します。

- **安定版**（正式に公開された版だけ）と **テスト版**（公開前の版も）を選べます。
- 自動では確認しません。確認するときに配布元（GitHub）へ送るのは、版を尋ねるリクエストだけです。
- 記録と設定はそのまま引き継ぎます。新しい版を起動できなかったときは、自動で前の版に戻します。

## やめる（アンインストール）

`%LOCALAPPDATA%\Programs\LabLog\uninstall.cmd` を実行します。自動起動とスタートメニューのショートカットを消し、LabLog を外します。記録したデータ（`%LOCALAPPDATA%\LabLog`）も消すかどうかは聞かれます（初めは残します）。

## 入退室の判定

設定の画面の **入退室の判定** で、判定のしかたを選びます。

| 判定方法 | 入室 | 退室 |
|---|---|---|
| Wi-Fi で判定する | 「研究室」として登録した Wi-Fi につながる | 登録していない Wi-Fi につながる。Wi-Fi が切れたら仮退出にし、4 時間戻らなければ退室 |
| この PC の操作で判定する | この PC を手元で操作し始める | 15 分操作がない・ロックしたら仮退出にし、4 時間戻らなければ最後に操作した時刻で退室 |
| 手動で記録する | 日別画面の「入室する」 | 日別画面の「退室する」（押し忘れたまま 4 時間操作がなければ、最後に操作した時刻で退室） |
| 記録しない | — | — （PC作業時間だけを記録し、場所は「自宅」か「その他」として数える） |

- **Wi-Fi の登録**：研究室にいるときに、設定の画面で「研究室として登録」を押します。研究室専用と大学共通の Wi-Fi（ScienceTokyo など）は、どちらも登録します。eduroam や Wi2 は他の場所にもあるので登録しません。iPhone のテザリングのように研究室でも外でも使う Wi-Fi は「判定に使わない」にします。
- **手動の入室・退室**：「記録しない」以外では、日別画面の研究室のタイルにある「入室する」「退室する」で切り替えられます。押し忘れたときは「時刻を指定…」で、実際に来た時刻・帰った時刻を入れられます。
- **リモートデスクトップ**：Windows のリモートデスクトップで外から操作している間は、研究室にいないとみなし、作業時間は「自宅」として数えます（Chrome リモートデスクトップなど、画面をそのまま映すソフトは見分けられません）。
- **滞在時間** は、PC を閉じてゼミに出ていた時間（仮退出から戻るまで）も含みます。**PC作業時間** は、5 分以上操作がなかった時間（離席）を除き、研究室・自宅・その他に分けて集計します。
- 1 日は朝 5 時で区切ります。深夜の作業は前日分です。夜通しいた場合も 1 回の滞在として記録します。
- 判定がずれたときは、日別画面の「入退室の記録」から時刻を直したり、追加・削除したりできます。
- 4 時間・15 分・5 分などの時間は設定で変えられます。

## 記録するもの

どれも初期設定で一つずつ選び、あとから設定の画面の **記録する材料** で変えられます。

| 材料 | 内容 |
|---|---|
| アプリとウィンドウ | 前面にあるアプリ名とウィンドウ名、使っていた時間（5 秒ごとに確認）。「アプリ名だけ」「記録しない（PC作業時間だけ）」も選べます |
| ファイル | 監視フォルダ内で作成・保存・削除・名前変更したファイル（パス・時刻・サイズだけ。中身は読まない） |
| Git | 監視フォルダ内のリポジトリのコミット、未コミットの変更数 |
| ブラウザ履歴 | Chrome・Edge で開いたページの URL とタイトル（シークレット／InPrivate は対象外）。画面に表示したページだけを表示・日報に使い、開いたままのタブがバックグラウンドで読み込まれただけのものは除きます |
| 最近使ったファイル | Windows の「最近使ったファイル」の一覧 |
| Claude Code の会話 | 会話の題名・作業フォルダ・やりとりした時刻（分単位）。ウィンドウ名が「Claude」だけのときに、この題名で補います。会話の中身は記録しません |
| 画面の文字 | 対象のアプリ（初期設定は Claude・ChatGPT・To Do・Teams・Zoom・MATLAB・ターミナル・PowerShell。ウィンドウ名から作業内容が分からないもの）が前面にあるとき、5 分に 1 回そのウィンドウだけを写し、Windows 標準の文字認識で文字にしたもの。画像は保存せず、文字は 3 日で消します。スマホには送りません |

- 初期設定を終えたあとも、閲覧履歴などは **初期設定を終えた時刻より後** の分だけを取り込みます。
- 上部の **■（記録を一時停止）** を押すと、作業内容の記録（上の表のすべて）を止めます。入退室の判定は続けます。止めている間は **▶（記録を再開）** に変わります。
- 画面の文字の読み取りは、2 分以上操作していないときや「記録しないアプリ」でも行いません。読み取った文字は日別画面の「画面から読み取った文字」で確かめられ、設定の「ウィンドウ名から分からない作業」でまとめて消せます。
- 設定の **記録しないアプリ** に入れたアプリは、時間だけを「(除外)」として残し、名前とウィンドウ名は記録しません。
- 分類（コーディング・解析／文書・資料作成 など）のルールは設定で変えられ、過去の記録にも反映されます。

## コミットの通知

監視フォルダ内のリポジトリで、ファイルを編集しているのに 2 時間以上コミットしていないと、Windows の通知で知らせます。
一度知らせたら、同じ時間がたつまで再通知しません。時間と通知のオン・オフは設定で変えられます。

## 日報

日報のつけ方は、初期設定で選びます（あとから設定の画面の「ローカルAI」の欄でも変えられます）。

- **自動で下書きを作る**：退出が確定したときと、日付が変わったときに、その日の記録から下書きを作ります。日別画面で書き直して「保存」すると、自動では上書きしなくなります。
  - AI を使わないとき：集計から箇条書きの下書きを作ります。
  - AI を使うとき：記録を要約して文章の下書きを作ります（1 日分で 1 分ほど）。メール・ファイル整理・分類できなかったサイト（動画など）・中身の分からないウィンドウは、AI に渡す前に除いています。
- **自分で書く**：自動では作りません。日別画面の「書く」で書きます（「下書きを作成」で下書きを作ることもできます）。

### ローカルAI（Ollama）

初期設定の画面で「AI を使う」を選ぶと、Ollama が入っているかを調べ、入っていなければボタンでインストールとモデルのダウンロードまで行えます。PC のメモリに合わせて、モデル（16 GB 以上なら `qwen3:8b`、8 GB 以上なら `qwen3:4b`）を勧めます。

手で入れるときは、`winget install Ollama.Ollama`（または https://ollama.com から）で Ollama を入れ、`ollama pull qwen3:8b`（約 5GB）でモデルをダウンロードします。設定の画面で「準備完了」と表示されれば使えます。

LabLog は `127.0.0.1`（この PC）の Ollama にしか接続しません。PC 外の URL は設定できないようにしてあり、プロキシも使いません。
Wi-Fi を切った状態でも日報を作れるので、外部に送っていないことを確かめられます。

## 画面の演出

その日の作業時間に応じて、ページの背景（壁紙）とカードが少しずつ豪華になります。この度合いを「フロー」と呼び、日別画面の「研究室・PC作業時間」のタイルの右上に 4 つの目盛りで出します。触れる（マウスを重ねる）と、フローが深まるまでの時間が出ます。

| フロー | 目安（PC作業時間。大学にいた時間の 75% のほうが長ければそちら） | 見た目 |
|---|---|---|
| 0 | 1 時間未満 | 灰色の地に白いカード（地味） |
| 1 | 1 時間〜 | 背景にうっすら青い光 |
| 2 | 3 時間〜 | 青・緑・紫の光、カードがすりガラスに |
| 3 | 5 時間〜 | 青・紫・ピンク・オレンジの光、数値のタイルに光る縁取り（研究室・PC作業時間のタイルは半透明のまま） |
| 4 | 7 時間〜 | いちばん鮮やかな光がゆっくり動く |

- 月の画面は、作業した日の平均でフローが決まります。設定画面はいつもフロー 0 です。
- タイムラインや分類別の色は意味を持つので変えません。
- 見た目を確かめるときは、URL に `?level=4` を付けるとフローを固定できます（例：`http://127.0.0.1:8765/?level=4`）。
- 日報は罫線入りのノート風に、手書き風の文字で表示します。文字は Klee One（SIL Open Font License 1.1。`lablog/web/fonts/OFL.txt`）を日本語の常用範囲に絞って同梱しています。

## iPhone・iPad で見る

PC と同じ画面を、iPhone・iPad の Safari で開けるビューアーがあります（URL は設定の画面の「iPhone・iPad で見る」に出ます）。
Safari の共有ボタン →「ホーム画面に追加」で、アプリと同じようにアイコンから開けます。

- **必要なもの**：個人の Microsoft アカウントと、この PC で同期している個人用の OneDrive（大学の Microsoft アカウントでは使えません）。
- **しくみ**：PC の LabLog が要約を OneDrive のアプリ専用フォルダ（`OneDrive\アプリ\LabLog`）に書き出し、ビューアーは個人の Microsoft アカウントでサインインしてそれを読みます。ビューアーが触れるのはこのフォルダだけです。
- **OneDrive に置くもの**：入退室・滞在時間・PC作業時間（大学／自宅）・分類別の時間・タイムラインの分類・日報。
- **PC だけに残すもの**：ウィンドウ名、閲覧したページ、編集・使用したファイル、Git、Wi-Fi 名。記録そのもの（`lablog.db`）も OneDrive には置きません。
- **書き出すタイミング**：5 分ごと（変わった分だけ）と、入退室・日報の作成・保存・滞在の修正のとき。設定の「今すぐ書き出す」でもすぐ書き出せます。
- **iPhone・iPad で直す**：日報の書き直しと滞在の追加・修正・削除ができます。直した内容は OneDrive の `edits` に置かれ、PC の LabLog が次に動いたとき（30 秒ごとに確認）に取り込みます。それまでは「PC へ反映待ち」と表示します。
- **始め方**：ビューアーを開いてサインインすると、OneDrive に `アプリ\LabLog` フォルダができます。PC の LabLog は目印の `viewer.json` を見つけると（数分以内）、書き出しを始めます。
- 書き出しを止めたいときは、設定の「iPhone・iPad で見る」で「OneDrive に書き出す」を外します。

## データの保存場所

`%LOCALAPPDATA%\LabLog`（OneDrive の外なので、クラウドには同期されません。アプリを更新しても、そのまま引き継ぎます）

| ファイル | 内容 |
|---|---|
| `lablog.db` | 記録（SQLite）。表の形を変える更新の前には `backups` フォルダに写しを作ります |
| `settings.json` | 設定 |
| `dashboard.key` | ダッシュボードの合言葉（この Windows のアカウントだけが開けるようにするためのもの） |
| `lablog.log` | 動作ログ（困ったときに見る） |

月ごとの入退室は、月画面の「CSV で書き出す」から Excel で開ける形式で保存できます。
ダッシュボードは `127.0.0.1` だけで待ち受けるので、同じ Wi-Fi の他の人からは開けません。同じ PC の別のアカウントからも開けません。

## 困ったとき

- **「LabLog から開き直してください」と出る**：ブックマークなどから直接開いたときに出ます。スタートメニューの LabLog から開き直してください（一度開けば、次からはそのブラウザで開けます）。
- **Wi-Fi が「未接続」のままになる**：Windows の設定 → プライバシーとセキュリティ → 位置情報 で「デスクトップアプリに位置情報へのアクセスを許可する」をオンにしてください（Windows の仕様で、Wi-Fi 名の取得に必要な場合があります）。
- **ダッシュボードが開かない**：ポート 8765 を他のアプリが使っている可能性があります。`settings.json` の `port` を変えて、LabLog を起動し直してください。
- **更新したあとに「前の版に戻しました」と出る**：新しい版を起動できなかったので、自動で前の版に戻しています。`%LOCALAPPDATA%\Programs\LabLog\launcher.log` を添えて、LabLog を配った人に知らせてください。

## 開発者向け

- Python 3.11 以降の標準ライブラリだけで動きます（追加のインストールは不要）。
- リポジトリのフォルダから動かすとき：`python LabLog.pyw`。ログオン時に自動で起動するには `install_autostart.ps1`、やめるには `uninstall_autostart.ps1` を実行します（このときは LabLog の画面からは更新せず、`git pull` で更新します）。
- テスト：`python -m unittest`
- 本番のデータと分けて試すとき：`python LabLog.pyw --port 8766 --data-dir <テスト用フォルダ>`
- ビューアーを PC で試すとき：`python tools/preview_viewer.py`（いまの記録の写しを使い、サインインなしで `http://127.0.0.1:8770/` に開く）
- ビューアーを公開し直すとき：`python tools/publish_viewer.py --push`（`lablog/web` の画面ファイルを `..\lablog-viewer` に写して GitHub の gh-pages ブランチに送る。記録は含めない）

### リリースの手順

1. `lablog/__init__.py` の `__version__` を上げます（正式な版は `1.1.0`、テスト版は `1.1.0b1` のように）。
2. テストを通します（`python -m unittest`）。
3. `python tools/release.py` で、`dist/LabLog-<版>.zip` を作ります。
4. GitHub の [Releases](https://github.com/ISCT-STLab/lablog/releases) で「Draft a new release」を押し、タグを `v<版>` にして、ZIP を添付し、変更点を書いて公開します。テスト版のときは「Set as a pre-release」に印を付けます。
   - `gh` を入れていれば：`gh release create v<版> dist/LabLog-<版>.zip --title "LabLog <版>" --notes-file <変更点.md>`（テスト版は `--prerelease` を付ける）
5. ブラウザ版（ビューアー）の画面も変えたときは、`python tools/publish_viewer.py --push` で公開し直します。

LabLog の「更新を確認」は、GitHub の API を認証なしで使います。リポジトリが公開されていないと、新しい版を見つけられません。
